## 1. Architecture Spine

```
Blazor page (.razor)
  → IXxxHandler                    Web.BlazorServer/Handlers/Repositories/[Feature]/
    → XxxHandler                   Web.BlazorServer/Handlers/Implementations/[Feature]/
      → IMediator.Send(XxxCmd/Qry)  Application.UseCases/Commands|Queries/[Feature]/
        → IXxxIntegration           Application.UseCases/Repositories/Integration/
          → Integration.NS          SuiteQL reads + NetSuite REST writes
```

### 1.1 Projects

| Project | Role |
|---|---|
| `Domain.Entities/` | DDD aggregates, value objects, enums, domain events |
| `Application.DataTransferObjects/` | DTOs only |
| `Application.UseCases/` | MediatR handlers, repository/integration interfaces, Mapster, pipeline behaviors |
| `Shared.Libraries/` | `DataGridIntent`, `AppAction`, `ApiResult`, `ICurrentUserService`, ViewModels |
| `Shared.DataCipher/` | `Encryption.Encrypt` / `Decrypt` |
| `Database.Libraries/` | `ISqlQueryManager` + Dapper script executor |
| `Database.MsSql/` | `AppDbContext`, EF configs, migrations, seeding |
| `Integration.NS/` | **Active** NetSuite integration (SuiteQL + REST + RESTlets) |
| `Integration.SAP/` | **Legacy SAP B1 — NOT registered in DI** |
| `Api.CoreWebAPI/` | JWT REST API consumed by `Mobile.MAUI` |
| `Web.BlazorServer/` | Blazor Server UI, cookie auth, Handlers, ViewModels |
| `Mobile.MAUI/` | MAUI Blazor Hybrid client (Zebra scanner) |

### 1.2 Where State Lives

**Local MSSQL (EF Core) owns only:**
- `OUSR` users · `OROL` roles · `USR3` user permissions · `ROL1` role permissions
- `OMPR` module permissions · `OMDL` modules · `ONRT` navigation routes
- `ODCT` document types · `ODCN` document number series · `OSTN` settings
- `OICD`/`ICD1`/`ICD2`/`ICD3` — **Inventory Counting only**

**NetSuite owns every other business document.**

### 1.3 Transaction Pipeline

`Application.UseCases/Behaviors/TransactionalDocumentBehavior.cs` is the **only** pipeline behavior.
It wraps any `ITransactionalRequest<T>` in Begin/Commit/Rollback. There is **no domain-event
dispatch behavior**, so domain events raised by entities are never delivered.

### 1.4 Startup Order

`Web.BlazorServer/Program.cs`:
`AddDatabaseMsSqlServices` → `AddDatabaseLibrariesServices` → **`AddNSServicesIntegraton`** →
`AddSharedServices` → `AddAppUseCases` → Radzen → handlers → cookie auth +
`AppPolicyProvider` / `AuthorizationController` / `AppAuthenticationStateProvider`.

Post-run: `InitializeAppDb.InitializeAppDbAsync` → `EnsureCreatedAsync` → `MigrateAsync` → `SeedData`.

## 3. Status & Approval Vocabulary

### 3.1 Approval Status (NetSuite `CUSTOMLIST_DBTI_CR_APPROVAL_STATUSES`)

Read via SuiteQL as `t.custbody_dbti_custom_approval_status`.

| Id | Meaning | Editable in WMS? |
|---|---|---|
| 1 | None / initial | Yes |
| 2 | Draft | **Yes** |
| 3 | Rejected | **Yes** |

**Editability rule** (identical in STR and ITR):
```csharp
IsEditable = !IsSubmittedForApprovals && (StatusId == 2 || StatusId == 3);
```
```csharp
public bool IsSubmittedForApprovals => SubmittedForApprovals.ToLowerInvariant().Equals("t");
```

### 3.2 Dormant Local Enums

`Domain.Entities/Enums/Transaction/Commons/ApprovalStatus.cs` —
`None=0, ForApproval=1, OngoingApproval=2, ForReview=3, Rejected=4, Approved=5`

`TransactionalDocumentDEM.SetApprovalStatus` enforces monotonic progression, but
**`SetApprovalStatus` is never called anywhere in the solution.** Only
`InventoryCountingDocumentDEM` persists the column, and it stays `None` forever.

`Domain.Entities/Enums/Transaction/Commons/DocumentStatus.cs` —
`Open, Closed, Cancelled, A(ForApproval), B(PendingReceipt), D(PartiallyReceived),
E(PendingBilling), F(FullyBilled), G(Closed), H(Rejected)`

Used only by `MarketingDocumentDEM` / `ReceivingDocumentDEM`. **STR/ITR do not use it.**

### 3.3 NetSuite Document Status (`t.status`)

| Code | Meaning | Appears in |
|---|---|---|
| `B` | Pending Receipt | Packing pool |
| `D` | Partially Received | Packing pool |
| `E` | Pending Billing | **Both** packing and receiving pools |
| `F` | Fully Billed | Receiving pool |

**Packing filter:** `status IN ('B','D','E')`
**Receiving filter:** `status IN ('F','E')`

### 3.4 Item Fulfillment Status

| Code | Meaning |
|---|---|
| `B` | Packed — awaiting trip ticket |
| `C` | Shipped — trip ticket done (or exempted) |

### 3.5 Inventory Status (per line)

| Id | Meaning |
|---|---|
| `1` | Good |
| `3` | Bad / Confiscated |
| `6` | Missing (mobile only) |

### 3.6 Transfer Category (`custbody_dbti_transfer_category`)

| Id | Meaning | IsInterCompany | IsReturn |
|---|---|---|---|
| 1 | Transfer | false | false |
| 2 | Intercompany Transfer | true | false |
| 3 | Return – Good Items | true | true |
| 4 | Return – Bad Items | true | true |

### 3.7 Trip Ticket

- `custrecord_dbti_trt_status: 8` = Cancelled (hard-coded, see `UpdateTripTicketPayloadDTO.cs:93`)

## 4. Flow Group 1 — The Core Transfer Chain

```
 ┌──────────────┐
   │ 1. STR      │  Create / Update / Submit-for-Approval
   │  (OSTR)      │  → NetSuite transferorder
   └──────┬───────┘
          │ (NetSuite approval workflow, outside WMS)
          ▼
   ┌──────────────┐
   │  2. PACKING  │  Item Fulfillment, shipStatus B or C
   │  (OPCK)      │  → NetSuite itemFulfillment
   └──────┬───────┘
          │  if shipStatus == 'B' (not trip-ticket exempt)
          ▼
   ┌──────────────┐
   │  3. TRIP     │  PATCH shipStatus→C, then RESTlet 1862
   │  TICKET      │  → customrecord_dbti_trip_ticket
   │  (OTTX)      │
   └──────┬───────┘
          │  IF now status='C' → visible in Receiving ▼
   ┌──────────────┐
   │  4. RECEIVING│  Item Receipt (good / bad / missing)
   │  (ORCV)      │  → NetSuite itemreceipt
   └──────────────┘
```

### 4.1 Stock Transfer Request (STR) — `OSTR`

**Routes** (`StockTransferRequest/STRRoutes.cs`):
- `/transactions/stocktransferrequest`
- `/transactions/stocktransferrequest/Create`
- `/transactions/stocktransferrequest/View?ref={tranid}`
- `/transactions/stocktransferrequest/Update?ref={tranid}`

**Pages** (`Web.BlazorServer/Components/Pages/Transaction/StockTransferRequest/`):
`StockTransferRequestPage` (3 tabs), `StockTransferRequestCreate`, `StockTransferRequestView`,
`StockTransferRequestUpdate`, `Components/STRForm.razor`, `Components/STRDataGrid.razor`

**Tabs**: `transferorder` · `intercompany` · `returns`

**Steps:**

1. **Create** — `StockTransferRequestCreate.razor`

     **Preferred Vendor required on every line**, Requested By required
   - `CreateStockTransferRequestCmd` → `StockTransferRequestIntegration.CreateStockTransferRequest`
   - `POST /record/v1/transferOrder` or `/record/v1/interCompanyTransferOrder`
   - Payload: `orderStatus = "A"`, `custbody_dbti_created_in_wms = true`,
     `custbody_dbti_prepared_by`, per-line `custcol_dbti_vendor`

2. **View** — `StockTransferRequestView.razor`
   - `GetStockTransferRequestQry` → header + lines via SuiteQL

   - Renders `STRForm` with `ReadOnly` when not editable

3. **Update** — `StockTransferRequestUpdate.razor`
   - Guard on load: `if (!response.IsEditable) throw`
   - `UpdateStockTransferRequestCmd` → `PATCH /{type}/{id}?replace=item`

4. **Submit for Approval** — button on read-only form
   - `SubmitStockTransferRequestForApprovalCmd`
   - `PATCH /{type}/{id}` `{"custbody_dbti_submitted_for_approval":true}`
   - Button self-hides: `CanBeSubmittedForApprovals = !IsSubmittedForApprovals && IsEditable`

5. **Approve / Reject** — ⛔ **not in the WMS.** A NetSuite workflow writes
   `custbody_dbti_custom_approval_status`. Rejected (3) → editable again.

6. **Print** — NetSuite scriptlet **1671** (`Web.BlazorServer/Components/Shared/Others/NetSuitePrint.cs`)

### 4.2 Packing → Item Fulfillment — `OPCK`

**Route**: `/transactions/delivery/packing` (4 tabs) — `Packing/PackingRoutes.cs`
**Sub-routes**: `/stock-transfer-request/view`, `/create-item-fulfillment`,
`/returns/view`, `/returns/create-item-fulfillment`,
`/vendor-return-authorization/view`, `/vendor-return-authorization/create-item-fulfillment`

**Pages**: `PackingPage.razor` → per tab:
`Packing/STR/Component/STRPackingDataGrid.razor` → `STRPackingDetails.razor`
→ `Packing/STR/ItemReceipt/PackingItemReceiptCreatePage.razor` → `PackingItemReceiptForm.razor`

⚠ Despite the names, `PackingItemReceiptCreatePage` **creates an Item Fulfillment**.

**Candidate filter** (`StockTransferRequestPackingIntegration.cs:204-213`):
   ```csharp
   In("t.recordtype", ["intercompanytransferorder", "transferorder"]),
   In("t.custbody_dbti_transfer_category", ["1", "2"]),
   Equal("t.ordpicked", "F"),
   In("t.status", ["B", "D", "E"])   // Pending Receipt / Partially Received / Pending Billing
   ```
   plus `Equal("t.subsidiary", subsidiaryId)`.

   ⚠ Plus an **inner join** onto `SuiteQLFragments.PendingPackingLines` — every
   transaction with at least one open line where ordered > packed. `ordpicked`
   tracks *picking*, not *fulfilling*, and status stays in B/D/E while the
   fulfillment is only Packed, so without this a fully packed order re-appears
   on the list until the Trip Ticket ships it. Returns uses the same gate over
   category `3`/`4`; VRA uses it over `quantityshiprecv`.

**Steps:**

1. Load source lines via stored SuiteQL script `NS_TO_x_Packing_Get_Items` (script resolver)
2. `PostTransferOrderIFCmd` → **fail-closed exemption gate**:
   ```csharp
   var isTripTicketExempt = I*PackingIntegration.GetTripTicketExemption(orderNumber);
   if (isTripTicketExempt is null)
       return ApiResult<bool>.Failed("Could not verify trip-ticket exemption…");
   ```
   Rationale in code: guessing would post a Packed (`B`) status for an exempt order,
   stranding already-shipped goods.
3. `SaveTOItemFulfillment` → `POST /{orderId}/!transform/itemFulfillment`
   - **`shipStatus = IsTripTicketExempt ? "C" : "B"`**
   - `printLabel = true` always
   - Bad lines and good lines posted as **two separate calls**
   - Line: `orderLine`, `itemreceive`, `quantity`,
     `inventoryDetail.inventoryAssignmentList.inventoryAssignment.items[]`
     with `inventoryStatus = IsBad ? "3" : "1"` and resolved `binNumber`

**Exemption resolution** — `customrecord_dbti_trip_ticket_exemption`, joined on
from_location → to_location with `isinactive='F'`. Deliberately free of order-state
predicates so it stays resolvable after the order advances.

**Print** — NetSuite scriptlet **1922** (packing label)

### 4.3 Trip Ticket — `OTTX`

**Route**: `/transactions/delivery/trip-ticket` — `TripTicket/TripTicketRoutes.cs`
Sub-routes: `/create`, `/view?ref=`

**Pages**: `TripTicketPage.razor`, `TripTicketCVU.razor(.cs)` (shared Create/View/Update),
`Component/TripTicketDataGrid.razor`, `Component/TripTicketFulfillmentSelection.razor`,
`Component/ParentTripTicketDialog.razor`

**Mobile**: `/tripticket/create` — `Mobile.MAUI/Components/Pages/TripTicket/CreateTripTicketView.razor`

⚠ **Mobile scans Item Fulfillment numbers, not item barcodes.**

**Candidate pool** (`TripTicketIntegration.GetItemfulfillments`):
```sql
t.type = 'ItemShip' AND t.status = 'B'
AND (custbody_dbti_fully_received = 'F' OR IS NULL)
```

**Steps:**

1. Select Packed item fulfillments
2. **Step A — Change Ship Status:**
   `PATCH /record/v1/itemFulfillment/{id}` → `{"shipStatus":{"id":"C"}}`
   ⚠ **Sequential loop** — one HTTP call per IF.
3. **Step B — RESTlet `script=1862`:**
   - Create: `POST` — `TripTicketPayloadDTO.CreateTripTicket`
   - Update: `PUT` — `UpdateTripTicketPayloadDTO.UpdateTripTicket`
     (added IFs → `lines`, removed → `cancelledLines`)
   - Cancel: `PUT` — `UpdateTripTicketPayloadDTO.CancelTripTicket`
     (`custrecord_dbti_trt_status: 8`)
4. Fields: from/to subsidiary, destination, truck plate, driver, helper, seal,
   origin location, trip date (`MM/dd/yyyy`)

**Guards:**
- `CanEdit` requires `Parent == 0 || null` (child tickets are immutable)
- `CanCancel => FormData.Status == null`
- Validation: TripDate, ≥1 destination, driver, helper, origin location,
  truck plate, ≥1 fulfillment with `NetsuiteOrderInternalId > 0`

### 4.4 Receiving → Item Receipt — `ORCV`

**Routes** (`Web.BlazorServer/Components/Pages/Transaction/Receiving/`):
- `/transactions/purchasing/receiving` (tabs: purchase-order / transfer-order / returns)
- `/transactions/purchasing/receiving/purchase-order/view`
- `/transactions/purchasing/receiving/transfer-order/view`
- `/transactions/purchasing/receiving/returns/view`
- `/transactions/purchasing/receiving/create-item-receipt`

**Two front-ends, one semantic model:**

| | Web (`Web.BlazorServer`) | Mobile (`Mobile.MAUI`) |
|---|---|---|
| Capture | `BarcodeScannerDialog.razor` — keyboard-wedge into a `RadzenTextBox` | Zebra **DataWedge** broadcast |
| Dispatch | Dialog submit → `BarcodeScanned` event | `MauiProgram.BroadcastService` **static event** |
| Accumulator | `BarcodeStore` — batch review + revert | `GoodXItems` / `BadXItems` lists mutated live |
| Resolution | `GetBarcodeDataQry` → `CUSTOMRECORD_BARCODE_PER_UOM` | `BarcodeResolver` → `POST /Item/PerBarcode` (per scan, cached in-session) |

**NetSuite targets by source:**

| Source | Mobile controller | Command | NetSuite target |
|---|---|---|---|
| Transfer Order | `Receiving/TransferOrder/SaveScan` | `PostTransferOrderIRCmd` | `restlet script=1853` |
| Returns | `Receiving/Returns/SaveScan` | `PostReturnsIRCmd` | `transferOrder/{id}/!transform/itemReceipt` |
| Purchase Order | `Receiving/PurchaseOrder/SaveScan` | `PostPurchaseOrderIRCmd` | `purchaseOrder/{id}/!transform/itemReceipt` |

**Web path**: `ItemReceiptCreatePage.razor` → `ReceivingIntegration.PostItemReceipt` →
up to 3 concurrent posts split by inventory status, ordered **bad → good → missing**
(`INVENTORY_STATUS_ID_GOOD=1`, `_BAD=3`, `_MISSING=6`).

**Pre-flight guards in `ReceivingIntegration.PostItemReceipt`:**
- Unnumbered-line guard: any line with `LineNumber <= 0` → throw naming the item
- Over-receipt guard (non-PO): re-reads TO `quantityshiprecv` and refuses
  `allotted > QuantityRemaining` — because mobile receipts are TO→IR linked
  and invisible to IF-based math

**Receiving list filters:**
- Direct TO: `status IN ('F','E')`, `transactionlinetype = 'RECEIVING'`
- Via IF: `NS_TO_Get_Itemfulfillments.sql` **requires `t.status='C'`** ← the trip-ticket gate

**End state:** item receipts created; when `quantityshiprecv == quantity` the TO
auto-closes and `custbody_dbti_fully_received='T'` removes the IF from every open pool.

### 9.4 Auth — Two Coexisting Schemes

**(a) OAuth2 client-credentials + JWT client-assertion (primary)**
- JWT signed with **RSA-PSS (PS256)**, 3072-bit key loaded once via `Lazy<RSA>`
- `scope = "restlets rest_webservices"`, expiry 10 min
- `_tokenSemaphore(1,1)` double-checked refresh, refreshed 1 min early

**(b) OAuth1.0 HMAC-SHA256 (RESTlets)**
- Manual header build: nonce, unix timestamp, sorted query params + `oauth_*`

### 9.5 Resilience (`Integration.NS/Resilience/`)

**Classification** (`NetSuiteRequestClassifier`): `GET` → Read;
URL contains `/query/v1/` → Read; **everything else → Write**.

**Retry** (`NetSuitePipelines`, Polly v8):
| Profile | Retries |
|---|---|
| `InteractiveRead` | any `NetSuiteTransientException` |
| `InteractiveWrite` | **only HTTP 429** |

`MaxRetryAttempts = 1`, 5s constant delay with jitter.

**Transient classification** (`NetSuiteExceptionFactory`): 408, 429, all 5xx.
Everything else → `NetSuiteValidationException`.

**Concurrency limiter**: `static SemaphoreSlim(2)` per process (env
`NETSUITE_MAX_INFLIGHT_PER_PROCESS`), so two hosts stay under NetSuite's limit of 5.
Held **across the whole retry pipeline** so a 429 storm can't starve the limiter.

**HttpClient timeout**: 100s default (env `NETSUITE_HTTP_TIMEOUT_SECONDS`).

⚠ **No circuit breaker is configured** — only bounded retry + a hard limiter.
⚠ `NetSuiteGateUnavailableException` is defined but no distributed gate is wired.

### 9.6 Caching (`Integration.NS/Implementations/Others/Caching/`)

**Grid-result cache** (`GridResultCache` + `GridCacheStore`):
- Dedicated `MemoryCache`, `SizeLimit = 500`, TTL **60s**
- Key: `ns:grid:v1:{entity}:{method}:{user}:{hash}`
- Scope: `{UserId}:{NsSubsidiaryId}[:{nsEmployeeId}]` from `ICurrentUserService`
- **Cache bypassed entirely if the caller cannot be identified** (no cross-user leak)
- 64 striped single-flight gates (a per-key dictionary would leak)
- Exceptions are never cached
- Mutations call `Mutate(...)` → `Invalidate(entity)` prefix-evict

**Decorated:** Items, Receiving, StockTransferRequest, SupplierReturn,
TripTicket, InventoryAdjustment, InventoryTransferRequest

### 9.7 SuiteQL Query Builder

`SuiteQLQueryBuilder` — fluent, translates `DataGridIntent` filters to SuiteQL:
- `ComparisonOperatorEnum` → SuiteQL operators
- `Contains/StartsWith/EndsWith` → `LOWER(col) LIKE LOWER('%v%')`
- `DateTime` comparisons wrap in `TO_DATE(…, 'YYYY-MM-DD"T"HH24:MI:SS')`
- **`Build()` clamps limit to NetSuite's SuiteQL range 1..1000**

`ExecuteWithPaging<T>()` works around NetSuite requiring `offset % limit == 0`:
fetches the misaligned page plus the next page and stitches the result.

### 9.8 Row-Level Security

`SuiteQLQueryExtensions` reads the `com.direcbusiness.wms.nsAllowedSubsidiaries` claim:

```csharp
WithSubsidiaries(context, "t")                    // t.subsidiary IN (...)
WithFromOrToSubsidiaries(context, "t")             // subsidiary OR tosubsidiary // OR custbody_dbti_prepared_by = me
```

⚠ **`WithSubsidiaries` is commented out** in `GetStockTransferRequest`
(`StockTransferRequestIntegration.cs:268`) — the STR view page is not subsidiary-scoped.

## 10. Known Defects & Findings

### Critical1. **`StockTransferRequestView.razor:14`** — gated on `[AppAuthorizationAttribute("VIEW", "ORCV")]`
   (Receiving) instead of `OSTR`, while breadcrumbs say `ModuleCode="OSTR"`.

2. **`InventoryTransferRequestUpdate.razor:8`** — gated on `VIEW OITR`, not `UPDATE OITR`.
   A read-only user can PATCH NetSuite.

3. **`StockTransferRequestUpdate.razor:15`** — same issue, gated on `VIEW OSTR`.
   The seeded `UPDATE` permission for `OSTR` is **never used**.

4. **`Submit for Approval` is not permission-gated** in STR, ITR, or Supplier Return —
   only gated by `IsEditable`. Any user with `VIEW` can submit another user's draft.
   Combined with #3 and the missing subsidiary filter (#5), this is a real exposure.

### Correctness

5. **`StockTransferRequestIntegration.cs:268`** — `.WithSubsidiaries(...)` commented out
   on the STR header query. Cross-subsidiary document visibility.

6. **`StockTransferRequestDataGridNSDTO.cs:31`** — `IsEditable => StatusId == 3`,
   contradicting the header rule `{2,3}`. The value is never mapped to the VM,
   so grid rows never offer Edit.

7. **`InventoryCountingDocumentDEM.AddSheet`** forces sheets to `Synced` immediately,
   making `SyncInventoryCountingSheetCmd`'s `Async` guard unreachable for UI-created sheets.

8. **`InventoryCountingSheetCreatedEvent`** is orphaned — no raise site, and no
   domain-event dispatch behavior exists.

9. **`SaveInventoryCountingDocumentCmd`** throws when `Status == Recount`, so a recounted
   document can never be re-saved. Only `Recount` → `Posted` (after Post) is reachable.

10. **`TransactionalDocumentDEM.SetApprovalStatus`** is never called anywhere.

11. **`Integration.NS/NSScripts/*.cs`** — three empty marker classes explicitly excluded
    from compilation by the csproj. Vestigial.

### Performance

12. **`TripTicketIntegration.ChangeShipStatus`** — sequential `PATCH` loop, one HTTP call
    per item fulfillment. Slow and partially-failable on multi-IF tickets.

13. **`StockTransferRequestIntegration`** fetches the whole base set (1000/page, max 5000)
    and applies the `(purchase_category != 3 OR purchase_subcategory = 5)` predicate    **in memory** — because the SuiteQL OR-group caused a ~45s full scan.

14. **`GetTransferOrderList` / `GetReturnsList`** call `ExecuteSuiteQLQuery` directly
    instead of `query.ExecuteWithPaging` — paging inconsistency vs
    `GetIntercompanyTransferOrderList`.

### Data / Transactional

15. **NetSuite write retry only fires on HTTP 429.** A 5xx on a write is lost with no retry.
    This is a deliberate, defensible call (no durable write ledger exists), but it should
    be a conscious acceptance rather than an accident.

16. **`ReceivingIntegration.PostItemReceipt`** issues up to 3 concurrent posts. A partial
    failure leaves NetSuite in a mixed good/bad/missing state. Failures are collected into
    an `AggregateException`, but there is no compensation.

17. **`DocNumReadRepo`** calls `SP_GetNextDocumentNumber` at two sites, but only
    `APP_SP_GetNextDocumentNumber` exists.

### Security

18. **No `APPROVE` permission row is seeded.** `Permission.Approve = 4` exists in the enum
    and the authorization matrix renders an "Approve" column, but `AppDefaults.Permissions`
    omits it, so the column never appears and `HasPermission("APPROVE")` is always false.

19. **Passwords use symmetric encryption** (`Shared.DataCipher`), not a hash.
    `Encryption.Decrypt(user.Account.HashedPassword) == request.Login.Password`.

20. **3 seeded users share one password** (`B1Admin!`) with usernames `WMS-0001..0003`.

### Dead Code

21. `Integration.SAP/**` — real implementations, not registered in DI.
22. `PostTransferOrderCmd`, `PostReturnsCmd`, `PostPurchaseOrderCmd` — record declarations
    with no handler; the `…IRCmd` variants are the live ones.
23. `StockTransferRequestHandler.GetStockTransferRequestLines` and
    `GetStockTransferRequestsList` — both `throw new NotImplementedException()`.
24. `InventoryTransferRequestVM.ApprovalStatus` — never populated. Dead.
25. `CountingDocumentType.cs` — declared, never referenced.
26. `NetSuiteGateUnavailableException` — defined, never thrown.
27. `Components/Layout/NavMenu.razor` — dead template boilerplate (Home/Counter/Weather).
28. `InputType` enum — only used by the legacy SAP receiving path.
